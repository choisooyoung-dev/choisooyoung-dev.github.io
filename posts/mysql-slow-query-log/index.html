MySQL 슬로우 쿼리 로그(Slow Query Log)

느린 쿼리를 찾아내는 슬로우 쿼리 로그 설정 방법과, EXPLAIN과의 역할 차이를 정리한다.

게시 2026/08/31
By Sooyoung Choi
읽는 시간 5분

왜 필요한가

EXPLAIN으로 쿼리를 분석하려면, 먼저 “어떤 쿼리가 느린지”를 알아야 한다. 서비스에 쿼리가 수백 개씩 있는데 하나하나 다 EXPLAIN 돌려볼 수는 없다. 느린 쿼리를 자동으로 찾아주는 도구가 슬로우 쿼리 로그다.

설정

1
2

SET GLOBAL slow_query_log = 'ON';
SET GLOBAL long_query_time = 1; -- 1초 넘는 쿼리만 기록 (기본값 10초)
  • slow_query_log: 슬로우 쿼리 로그 기능 자체를 켜고 끄는 스위치
  • long_query_time: 몇 초 이상 걸린 쿼리를 “느린 쿼리”로 볼지 기준 (초 단위, 기본값 10초)

실무에서는 기본값(10초)이 너무 널널해서, 보통 0.5~1초 정도로 낮춰놓고 실제로 로그가 얼마나 쌓이는지 보면서 조정한다. 너무 낮추면(예: 0.1초) 로그가 과도하게 쌓여서 오히려 분석하기 힘들어지고, 너무 높이면 진짜 느린 쿼리를 놓친다.

SET GLOBAL로 설정하면 서버 재시작 시 초기화된다. 계속 유지하려면 my.cnf(설정 파일)에도 같이 적어둬야 한다.

1
2
3

[mysqld]
slow_query_log = 1
long_query_time = 1

로그에 뭐가 쌓이는가

설정해두면 조건에 걸리는 쿼리마다 자동으로 로그가 쌓인다. 대략 이런 정보가 담긴다.

  • 쿼리 실행 시간
  • 훑은(스캔한) row 수 (Rows_examined)
  • 실제로 반환한 row 수 (Rows_sent)
  • 실행된 쿼리문 자체
  • 실행 시각, 어느 커넥션/유저가 실행했는지

로그 파일 위치는 아래로 확인할 수 있다.

1

SHOW VARIABLES LIKE 'slow_query_log_file';

실제로 쓰는 흐름

  1. 슬로우 쿼리 로그를 켜고 일정 기간 운영한다. (하루, 일주일 등 트래픽이 실제로 발생하는 기간)
  2. 쌓인 로그를 확인해서, 반복적으로 걸리는 느린 쿼리를 추린다. (로그 양이 많으면 mysqldumpslow나 pt-query-digest 같은 도구로 요약해서 본다 — 같은 패턴의 쿼리를 묶어서 “얼마나 자주, 얼마나 오래 걸렸는지” 통계로 보여준다)
  3. 추려낸 쿼리를 EXPLAIN으로 분석해서 원인을 파악한다. (인덱스 유무, JOIN 비효율, 전체 스캔 여부 등 — B+Tree 글 참고)
  4. 원인에 맞게 인덱스 추가, 쿼리 재작성 등으로 개선한다.

EXPLAIN과의 역할 차이

도구 역할
슬로우 쿼리 로그 분석할 쿼리를 찾아주는 도구. “이 쿼리들이 느리다”는 후보를 자동으로 모아준다.
EXPLAIN 찾은 쿼리를 분석하는 도구. 왜 느린지(인덱스 미사용, 전체 스캔, JOIN 비효율 등) 실행 계획을 보여준다.

즉 슬로우 쿼리 로그로 “무엇을” 봐야 할지 찾고, EXPLAIN으로 “왜” 느린지 파악하는 두 단계로 이어지는 도구다. 슬로우 쿼리 로그 없이 EXPLAIN만 있으면 어떤 쿼리부터 봐야 할지 막막하고, EXPLAIN 없이 슬로우 쿼리 로그만 있으면 느린 쿼리 목록은 있지만 원인을 알 수가 없다.

정리

  • 슬로우 쿼리 로그는 long_query_time(기본 10초, 실무에선 보통 0.5~1초)을 넘는 쿼리를 자동으로 기록한다.
  • 로그에는 실행 시간, 스캔한 row 수 등 분석에 필요한 정보가 담긴다.
  • SET GLOBAL은 재시작 시 초기화되므로, 계속 켜두려면 설정 파일(my.cnf)에도 반영해야 한다.
  • 흐름은 슬로우 쿼리 로그로 후보 발굴 → EXPLAIN으로 원인 분석 → 개선 순서다.
