InnoDB Buffer Pool

InnoDB Buffer Pool이 디스크 I/O를 줄이는 방식, LRU 캐시 교체 정책, 적정 크기 설정과 워밍업까지 정리한다.

게시 2026/09/03
By Sooyoung Choi
읽는 시간 7분

같은 쿼리를 두 번 실행했을 때 두 번째가 훨씬 빠른 걸 경험해봤을 텐데, 그 이유의 대부분은 Buffer Pool 이다. InnoDB가 디스크 I/O를 줄이기 위해 메모리에 두는 캐시 영역이다.

Buffer Pool이 하는 일

  • 테이블/인덱스의 데이터를 디스크가 아니라 메모리에서 읽고 쓸 수 있게 캐싱하는 영역이다.
  • InnoDB는 데이터를 페이지(기본 16KB) 단위로 다룬다. 어떤 row를 읽으면 그 row가 속한 페이지 전체를 디스크에서 읽어 Buffer Pool에 올려두고, 이후 같은 페이지를 다시 읽을 땐 디스크가 아니라 메모리에서 바로 가져온다.
  • 쓰기도 마찬가지다. UPDATE를 실행하면 즉시 디스크에 쓰는 게 아니라 Buffer Pool의 페이지를 먼저 변경하고(이 상태를 dirty page라 부른다), 이후 백그라운드로 디스크에 flush한다. 커밋 시점엔 redo log에 변경 내용을 먼저 기록해서 안전성을 확보하고, 실제 데이터 파일 반영은 나중에 몰아서 처리한다.

쿼리 요청
  → Buffer Pool에 해당 페이지가 있는가? (Buffer Hit)
      있으면 → 메모리에서 바로 반환 (빠름)
      없으면 → 디스크에서 페이지를 읽어 Buffer Pool에 적재 후 반환 (Buffer Miss, 느림)

LRU로 무엇을 남길지 정한다

메모리는 한정돼 있어서 모든 데이터를 다 캐싱할 순 없다. InnoDB는 LRU(Least Recently Used) 를 개선한 알고리즘으로 어떤 페이지를 유지하고 어떤 페이지를 버릴지 정한다.

  • 그냥 LRU를 쓰면 문제가 생긴다 — 예를 들어 한 번의 대량 SELECT나 백업용 풀스캔이 실행되면, 자주 쓰이던 페이지들이 전부 밀려나고 한 번 스캔한 뒤 다시는 안 쓸 페이지들로 캐시가 가득 찬다.
  • 이를 막기 위해 InnoDB는 LRU 리스트를 new sublist(자주 접근) 와 old sublist(최근에 처음 들어옴) 로 나눈다. 새로 읽은 페이지는 일단 old 영역에 들어가고, 일정 시간 안에 다시 접근돼야 new 영역으로 승격된다.
  • 풀스캔으로 한 번 훑고 지나간 페이지들은 old 영역에만 머물다가 금방 밀려나므로, 자주 쓰이는 데이터(hot data) 가 대량 스캔 한 번에 캐시에서 통째로 밀려나는 걸 막아준다.

크기 설정

1
2

# my.cnf
innodb_buffer_pool_size = 8G
  • Buffer Pool이 클수록 캐시 적중률(Buffer Hit Ratio)이 높아져서 디스크 I/O가 줄어든다. 일반적으로 전용 DB 서버 메모리의 50~75% 정도를 권장값으로 잡는다 (OS와 다른 프로세스가 쓸 메모리는 남겨둬야 한다).
  • 너무 작으면 자주 쓰는 데이터조차 캐시에서 계속 밀려나 디스크 I/O가 잦아지고, 너무 크게 잡으면 OS 메모리가 부족해져 스왑이 발생해 오히려 느려질 수 있다.
  • Buffer Pool 상태는 다음으로 확인할 수 있다.

SHOW ENGINE INNODB STATUS\G

Buffer pool hit rate가 낮다면 Buffer Pool 크기가 부족하거나, 쿼리가 인덱스를 못 타서 불필요하게 많은 페이지를 읽고 있는 건 아닌지 EXPLAIN으로 같이 확인해봐야 한다.

재시작하면 캐시가 비워진다 — 워밍업

  • MySQL을 재시작하면 Buffer Pool은 초기화된다. 재시작 직후엔 캐시 적중률이 낮아 디스크 I/O가 몰리면서 일시적으로 느려지는 콜드 스타트 상태가 된다.
  • InnoDB는 이를 완화하기 위해 innodb_buffer_pool_dump_at_shutdown / innodb_buffer_pool_load_at_startup 옵션을 제공한다. 종료 시점에 어떤 페이지들이 캐시에 있었는지 목록만 디스크에 저장해두고, 재시작할 때 그 목록을 참고해서 같은 페이지들을 미리 다시 읽어들인다 (데이터 자체가 아니라 “어떤 페이지가 있었는지”만 기록하므로 저장 크기가 작다).
  • 운영 서버는 이 옵션들을 켜두면 재배포/재시작 직후의 성능 저하 구간을 줄일 수 있다.

정리

  • Buffer Pool은 InnoDB가 디스크 I/O를 줄이기 위해 데이터/인덱스 페이지를 메모리에 캐싱하는 영역이다.
  • 페이지 단위(기본 16KB)로 캐싱하고, 개선된 LRU로 대량 스캔 한 번에 자주 쓰는 데이터가 밀려나지 않게 관리한다.
  • 크기는 보통 서버 메모리의 50~75%, SHOW ENGINE INNODB STATUS로 적중률을 확인하며 조정한다.
  • 재시작 시 캐시가 비워지는 콜드 스타트 문제는 dump_at_shutdown / load_at_startup으로 완화할 수 있다.
