Git 실습 2: staging 영역과 status 두 글자 읽기

같은 파일에 staged 변경과 unstaged 변경을 함께 만들어 Git status의 두 열과 diff의 차이를 관찰한다.

게시 2026/09/11
By Sooyoung Choi
읽는 시간 4분

git add를 한 뒤 같은 파일을 다시 수정하면 어떻게 될까? 이번 실습에서는 한 파일에 staged 변경과 unstaged 변경을 동시에 만들어 git status --short의 두 글자가 무엇을 뜻하는지 살펴본다.

두 번 수정하기

README에 첫 번째 내용을 추가하고, 새 메모 파일도 만든다.

1
2

echo "첫 번째 수정" >> README.md
echo "Git 명령어 정리" > notes.txt

두 파일을 스테이징한다.

1

git add README.md notes.txt

그 후 README만 다시 수정한다.

1
2

echo "두 번째 수정" >> README.md
git status --short

1
2

MM README.md
A  notes.txt

status의 두 열

짧은 상태 출력의 두 글자는 각각 다른 영역의 차이를 나타낸다.

1
2
3

XY 파일명
│└─ Y: 스테이징 영역과 작업 디렉터리의 차이
└── X: 마지막 커밋과 스테이징 영역의 차이

따라서 MM README.md는 두 가지 변경이 동시에 있다는 뜻이다.

  1. 첫 번째 M: 마지막 커밋과 비교해 스테이징된 수정이 있다.
  2. 두 번째 M: 스테이징한 뒤 작업 디렉터리에서 다시 수정했다.

A notes.txt는 새 파일이 스테이징됐으며, 스테이징 후에는 추가로 바뀌지 않았다는 의미다.

어떤 내용이 커밋될까

Git은 파일의 최신 내용을 무조건 커밋하지 않는다. 마지막으로 git add한 시점의 내용을 커밋한다.

따라서 현재 바로 커밋하면 README의 첫 번째 수정은 포함되지만, 두 번째 수정은 포함되지 않는다. 두 번째 수정은 git add 이후에 생겼기 때문이다.

두 종류의 diff를 확인하면 이 차이가 분명해진다.

1
2

git diff --staged
git diff
  • git diff --staged에는 다음 커밋에 들어갈 첫 번째 수정과 notes.txt가 나온다.
  • git diff에는 스테이징 이후에 추가한 두 번째 수정이 나온다.

staged 내용만 커밋하기

1
2

git commit -m "docs: add first update and notes"
git status --short

1

 M README.md

앞 칸은 비어 있고 뒤 칸에만 M이 남았다. 첫 번째 수정과 notes.txt는 커밋됐고, README의 두 번째 수정만 작업 디렉터리에 남아 있다는 뜻이다.

핵심: add는 파일 등록이 아니라 스냅샷 준비다

git add를 단순히 “파일을 Git에 추가한다”라고만 기억하면 이 상황이 혼란스럽다. 더 정확한 의미는 현재 파일의 내용을 스테이징 영역에 복사해 다음 커밋의 스냅샷으로 준비한다는 것이다.

파일을 다시 수정해도 이미 스테이징된 내용이 자동으로 갱신되지는 않는다. 새 수정까지 커밋하려면 다시 git add README.md를 실행해야 한다.

정리

  • git status --short의 첫 열은 staged 상태, 둘째 열은 unstaged 상태다.
  • 같은 파일에 staged 변경과 unstaged 변경이 동시에 존재할 수 있다.
  • 커밋에는 파일의 최신 내용이 아니라 마지막으로 git add한 내용이 들어간다.
  • git diff --staged는 커밋 예정 내용, git diff는 아직 스테이징하지 않은 내용을 보여준다.
