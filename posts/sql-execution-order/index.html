SQL 실행 순서 - WHERE vs HAVING

WHERE와 HAVING의 역할 차이, SQL 실행 순서(FROM~ORDER BY)를 예제 쿼리로 정리한다.

게시 2026/08/31
By Sooyoung Choi
읽는 시간 3분

DML(SELECT) 쿼리를 짤 때마다 헷갈리는 WHERE vs HAVING, 그리고 SQL이 실제로 실행되는 순서를 정리한다.

WHERE

GROUP BY 하기 전에, 개별 Row를 거르는 역할.

아직 그룹이 만들어지기 전 단계라서, 원본 테이블의 각 행 기준으로 조건을 건다.

HAVING

GROUP BY가 다 끝난 뒤, 집계 결과를 거르는 역할.

그룹이 이미 만들어진 상태이므로, SUM, COUNT, AVG 같은 집계 함수를 조건으로 쓸 수 있다. (WHERE에는 집계 함수를 못 쓴다 — 아직 그룹이 없으니까)

SQL 실행 순서

작성 순서(SELECT ... FROM ... WHERE ... GROUP BY ... HAVING ... ORDER BY)와 실제 실행 순서는 다르다.

순서 절 하는 일
1 FROM 테이블 읽기. JOIN도 FROM의 일부로 이 단계에서 처리
2 WHERE 개별 Row 필터링 (아직 그룹 생성 X)
3 GROUP BY 그룹 생성
4 HAVING 그룹별 집계 결과 필터링 (이때부터 SUM, COUNT 등 집계 함수 사용 가능)
5 SELECT 실제 조회할 컬럼 선택
6 ORDER BY 정렬

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY 순서로 기억해두면, WHERE와 HAVING 중 뭘 써야 할지, 왜 WHERE에 집계 함수를 못 쓰는지가 자연스럽게 이해된다. (SELECT보다 GROUP BY/HAVING이 먼저 실행되기 때문에, SELECT에서 정한 별칭(alias)을 HAVING에서 못 쓰는 이유도 여기서 나온다.)

예제

EX) 2024년 이후(created_at >= '2024-01-01') 주문 중, 유저별 주문건수가 5건 이상인 유저를 찾는다면?

실행 순서대로 짚어보면:

  1. FROM orders o — orders 테이블 읽기
  2. WHERE o.created_at >= '2024-01-01' — 2024년 이후 주문만 개별 필터링 (아직 그룹 없음)
  3. GROUP BY o.user_id — 유저 단위로 그룹 생성
  4. HAVING COUNT(o.id) >= 5 — 그룹별 주문 개수가 5개 이상인 그룹만 필터링
  5. SELECT o.user_id — user_id만 조회
  6. ORDER BY o.user_id — 정렬

SELECT o.user_id
FROM orders o
WHERE o.created_at >= '2024-01-01'
GROUP BY o.user_id
HAVING COUNT(o.id) >= 5
ORDER BY o.user_id;

created_at 조건은 그룹과 무관하게 각 행에 바로 걸 수 있는 조건이라 WHERE에, 주문 건수는 그룹으로 묶은 뒤에만 셀 수 있는 값이라 HAVING에 들어간 걸 확인할 수 있다.

정리

  • WHERE: 그룹 생성 전, 개별 Row 필터링. 집계 함수 사용 불가.
  • HAVING: 그룹 생성 후, 집계 결과 필터링. 집계 함수 사용 가능.
  • 실행 순서는 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY. 작성 순서와 다르다는 걸 기억해두면 WHERE/HAVING 선택이 헷갈리지 않는다.
