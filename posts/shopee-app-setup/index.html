Shopee Open API 연동 준비 - 앱 생성부터 토큰 발급까지

Shopee Open API를 쓰기 위한 앱 생성, 앱 인증, 토큰 생성 과정을 정리한다.

게시 2026/08/27
By Sooyoung Choi
읽는 시간 9분

Shopee Open API를 연동하기 전에 거쳐야 하는 준비 과정을 정리한다. 순서는 크게 세 단계다.

  1. 쇼피 앱 생성
  2. 앱 인증
  3. 토큰 생성

⚠️ 주의: 쇼피 앱을 만들고 나면 바로 실사용(Live)으로 전환되지 않는다. Live 승인까지 24시간 정도 소요된다고 명시되어 있으니, 테스트/연동 일정을 잡을 때 이 대기 시간을 감안해야 한다.

1. 쇼피 앱 생성

Shopee Open Platform에 파트너 계정으로 로그인한 뒤 앱을 생성한다.

  1. Console > App Management > Create App 진입
  2. 앱 이름, 앱 설명 등 기본 정보 입력
  3. 사용할 API 스코프(주문/상품/물류 등 필요한 권한) 선택
  4. 생성 완료하면 Partner ID, Partner Key가 발급된다 — 이후 모든 API 요청 서명(signature)에 사용되는 값이라 안전하게 보관해야 한다.

앱을 생성한 시점에는 Test(테스트) 상태다. 실제 판매자 데이터를 다루려면 Shopee 측 심사를 거쳐 Live 상태로 전환 승인을 받아야 하고, 이 승인에 보통 24시간 정도가 소요된다. 테스트 환경(Sandbox)에서 먼저 연동을 검증해두고, Live 전환은 미리 신청해두는 게 일정 관리에 유리하다.

App List 화면을 보면 앱 하나당 Test Partner_id / Live Partner_id가 따로 발급되어 있는 걸 확인할 수 있다. Sandbox 연동 테스트는 Test Partner_id로, 실제 서비스 연동은 Live Partner_id로 한다 — 서로 다른 키라서 헷갈리지 않게 환경변수부터 분리해두는 게 좋다.

App List 화면. Test/Live 각각 Partner_id와 Authorize 버튼이 따로 있다.

2. 앱 인증 (Authorization)

앱 자체를 만들었다고 바로 API를 호출할 수 있는 건 아니고, 판매자(Shop) 계정이 이 앱에 권한을 위임(인증)해줘야 한다. App List 화면에서 Test/Live Partner_id 옆에 있는 “Authorize” 버튼을 누르는 것으로 시작한다.

  1. App List에서 Authorize 클릭 → Redirect URL을 입력하는 창이 뜬다. (콜백을 받을 내 서버 주소)
  2. Redirect URL을 입력하고 나면 로그인 화면으로 이동한다. 판매자 계정으로 로그인 후 Authorization(권한 허용)을 진행한다.
  3. 인증이 완료되면, 방금 입력한 Redirect URL로 code와 shop_id가 붙어서 콜백된다.

콘솔에서 수동으로 테스트할 땐 이렇게 버튼 클릭 → Redirect URL 입력 순서로 진행하면 되고, 이걸 코드로 자동화하려면 (Redirect URL을 포함한) 인증 URL 자체를 직접 생성해서 판매자에게 보여주면 된다 — 내부적으로 Shopee가 만드는 URL이 바로 /api/v2/shop/auth_partner이고, 아래 코드가 그 URL을 만드는 방법이다.

이 code가 다음 단계(토큰 생성)에서 실제 액세스 토큰과 교환하는 데 쓰인다. code는 유효 시간이 짧으므로(보통 10분 내) 발급받으면 바로 토큰 발급 요청으로 이어가야 한다.

인증 URL 만드는 코드

Shopee Open API는 요청마다 partner_id + api_path + timestamp를 partner_key로 HMAC-SHA256 서명해서 sign 파라미터로 붙여야 한다.

import crypto from "crypto";

const PARTNER_ID = Number(process.env.SHOPEE_PARTNER_ID);
const PARTNER_KEY = process.env.SHOPEE_PARTNER_KEY!;
const REDIRECT_URL = "https://your-domain.com/shopee/callback";

function sign(path: string, timestamp: number): string {
  const baseString = `${PARTNER_ID}${path}${timestamp}`;
  return crypto
    .createHmac("sha256", PARTNER_KEY)
    .update(baseString)
    .digest("hex");
}

export function buildAuthUrl(): string {
  const path = "/api/v2/shop/auth_partner";
  const timestamp = Math.floor(Date.now() / 1000);
  const signature = sign(path, timestamp);

  const url = new URL(`https://partner.shopeemobile.com${path}`);
  url.searchParams.set("partner_id", String(PARTNER_ID));
  url.searchParams.set("redirect", REDIRECT_URL);
  url.searchParams.set("timestamp", String(timestamp));
  url.searchParams.set("sign", signature);

  return url.toString();
}

이렇게 만든 URL을 판매자에게 보여주면, 판매자가 로그인 + 권한 허용 후 아래처럼 입력했던 Redirect URL 뒤에 code와 shop_id가 쿼리스트링으로 붙어서 콜백이 온다.

1

https://your-domain.com/shopee/callback?code=7a2f9c1e...&shop_id=123456

내 서버(/shopee/callback 라우트)는 이 쿼리스트링에서 code, shop_id를 꺼내서 바로 다음 단계(토큰 발급 API 호출)로 넘기면 된다.

3. 토큰 생성 (Access Token 발급)

앞 단계에서 받은 code와 shop_id로 /api/v2/auth/token/get API를 호출해서 실제 토큰을 발급받는다. 이 요청도 마찬가지로 sign이 필요하다.

import axios from "axios";
import crypto from "crypto";

const PARTNER_ID = Number(process.env.SHOPEE_PARTNER_ID);
const PARTNER_KEY = process.env.SHOPEE_PARTNER_KEY!;

function sign(path: string, timestamp: number): string {
  const baseString = `${PARTNER_ID}${path}${timestamp}`;
  return crypto
    .createHmac("sha256", PARTNER_KEY)
    .update(baseString)
    .digest("hex");
}

export async function getAccessToken(code: string, shopId: number) {
  const path = "/api/v2/auth/token/get";
  const timestamp = Math.floor(Date.now() / 1000);
  const signature = sign(path, timestamp);

  const { data } = await axios.post(
    `https://partner.shopeemobile.com${path}`,
    {
      code,
      shop_id: shopId,
      partner_id: PARTNER_ID,
    },
    {
      params: {
        partner_id: PARTNER_ID,
        timestamp,
        sign: signature,
      },
    }
  );

  // data.access_token, data.refresh_token, data.expire_in
  return data;
}

응답으로 access_token과 refresh_token을 받는다.

  • access_token: 실제 API 호출(주문 조회, 상품 등록 등)에 사용. 유효 기간이 짧다 (보통 4시간).
  • refresh_token: access_token이 만료되면, 이 토큰으로 재발급받는다. refresh_token도 유효 기간이 있으므로(보통 30일) 그 전에 갱신해야 한다.

즉 access_token은 짧게 살고 refresh_token으로 계속 갱신해가며 쓰는 구조라서, 서버에서는 토큰 만료를 감지해서 자동으로 refresh하는 로직을 미리 만들어두는 게 좋다.

토큰 갱신(Refresh) 코드

/api/v2/auth/access_token/get으로 만료된 access_token을 refresh_token으로 재발급받는다. 구조는 토큰 발급 때와 거의 같고, code 대신 refresh_token을 보낸다는 점만 다르다.

export async function refreshAccessToken(refreshToken: string, shopId: number) {
  const path = "/api/v2/auth/access_token/get";
  const timestamp = Math.floor(Date.now() / 1000);
  const signature = sign(path, timestamp);

  const { data } = await axios.post(
    `https://partner.shopeemobile.com${path}`,
    {
      refresh_token: refreshToken,
      shop_id: shopId,
      partner_id: PARTNER_ID,
    },
    {
      params: {
        partner_id: PARTNER_ID,
        timestamp,
        sign: signature,
      },
    }
  );

  // 새로운 access_token, refresh_token으로 갈아끼운다
  return data;
}

실제로는 API 호출 전에 저장해둔 access_token의 만료 시각(expire_in 기준으로 계산)을 확인해서, 만료가 임박했으면 호출 전에 먼저 refreshAccessToken을 태우고 새 토큰으로 교체하는 방식으로 쓴다.

정리

  • 쇼피 앱은 생성 → (판매자) 인증 → 토큰 발급 순서로 준비한다.
  • 앱 생성 직후엔 Test 상태이고, Live 전환 승인에 약 24시간이 걸리므로 일정에 미리 반영해야 한다.
  • 인증 단계의 code는 유효시간이 짧아서 발급 즉시 토큰 교환까지 이어가야 한다.
  • access_token은 단명, refresh_token으로 주기적으로 갱신하는 구조이므로 자동 갱신 로직을 서버에 준비해두는 게 안전하다.
